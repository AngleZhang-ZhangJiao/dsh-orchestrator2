## 二、填写说明

- **状态词口径（四枚举，唯一）**：`已验证`＝现场实测通过（须附证据与日期）；`用户确认`＝用户裁决类信息（探查无法重建，如执行位置 / 远程仓库 / 测试服务器连接 / codegraph 降级裁定）；`未验证`＝尚未核实或已过期；`不适用`＝本次任务不需要该项，**须写理由**。**必要项未达「已验证」不放行**。
- **固定块维护**：`必要项`＝本次开发实际需要的条目数（≥1）；`未通过项`＝状态仍为「未验证」的条目数（**=0 才放行**）；`最近复查`＝最近一次复查日期（`YYYY-MM-DD`）。
- **`门禁结论` 字段（未通过 / 已通过）＝最近一次门禁复查结果的「人读记录」，机器不消费其值**——机器判定只看 `必要项` / `未通过项` / `最近复查` 三字段。因此「记录写未通过但机器放行」只可能是三字段确实达标，不是矛盾。
- **标准必要项候选**（按本次任务增删，不照抄）：插件级＝三角色模型配置与凭据可达 / codegraph 可用；项目级＝git 与 remote / 规范 v2.1 与六区脚手架 / 执行位置 / 测试环境连接 / 技术栈环境（按执行位置）/ codegraph 索引新鲜度（详见预设 persona【首次使用引导】探查清单）。
- **脱敏义务**：不含密钥、私钥、token、完整敏感连接串；远程仓库/服务器只写连接方式与必要标识。
- **变更时更新**：配置 / 仓库 / 执行位置变化后，调度员在下次首次对话引导或门禁复查时更新本记录；不做自动失效指纹，靠 `最近复查` 人读留痕。
