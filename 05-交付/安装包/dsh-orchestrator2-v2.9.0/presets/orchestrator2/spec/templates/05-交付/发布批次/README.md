# 发布批次 · 用途说明

> **区语义**：**批次执行记录**——本批含哪些任务、发布说明、批次清单。
> 与 `00-项目管理/发布批次规划.md` 分工：**规划 = 计划（00 区）**；**执行记录 = 本目录**。
> 位置：`05-交付/发布批次/`。本文件说明用途与维护规则；具体批次按批次建目录或建文件。

## 一、放什么

| 内容 | 说明 |
|---|---|
| 批次清单 | 本批包含的任务/包编号与其验收结论链接 |
| 发布说明 | 面向用户：本批新增/修复/变更了什么、已知限制 |
| 构建产物索引 | 对应 `05-交付/安装包/<名>-v<版本>/` 的版本号与 zip |
| 发布前置核对 | 各任务是否已 `已完成`（验收结论落盘）、全局回归是否通过 |
| 发布后记录 | 推送记录/部署记录链接（`05-交付/<TP>/推送记录-…`、`部署记录-…`） |

## 二、谁写、何时写

- **写入者**：调度员。
- **时机**：批次发布时（构建 → 全局回归 → 发布前置核对 → 推送/部署后回填）。
- **版本规则**：**按批次建目录**（如 `批次1-YYYYMMDD/`），批次内文件按需建立。

## 三、发布前置核对（缺一不可）

- [ ] 本批各任务 `03-开发协同/<TP>/状态.md` = `已完成`
- [ ] 各包 `04-测试/<TP>/验收结论.md` 已落盘（含债务清单段）
- [ ] 全局回归记录已落 `04-测试/全局回归/`，结论为放行
- [ ] 安装包版本号目录 + zip 就绪（含测试入口说明）
- [ ] 用户已确认发布（发布 = 交付动作，需用户明确指令）

## 四、不做什么

- **不**记录单任务级构建/推送/部署过程（那属于 `05-交付/<TP>/` 任务级三件记录）。
- **不**替代 `00-项目管理/发布批次规划.md` 的规划职责（本目录只记「实际发生了什么」）。
