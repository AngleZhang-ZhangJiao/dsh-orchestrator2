# 自动开发调度器（dsh-orchestrator 系列）

> DSH agent preset 插件：单会话双态——先以调度员身份与你交互完成产品设计（并行研究员调研 → 方案 → 决策清点 → 定稿），一句确认后切换为调度引擎，goal 驱动自动推进开发流水线（审核员计划审核 → 开发员执行自测 → 审核员 AC 证据核验+代码审查 → 调度员构建），推进到「待人工测试」硬停止等你实测；验收阶段走修复循环（T0~T3 证据链）。
>
> **当前版本：v2.9.0**（2026-10-08 发布）　|　**相对上版 v2.8.0 的差异**：引导/TP1-首次使用引导——persona 新增【首次使用引导】小节（新会话首次对话先做秒级只读探查：插件级 3 项＋项目级 6 项，只把缺的/未验证的准备事项告知用户；探查零副作用）；`enter_auto_mode` 新增**开发准备门禁**（项目根 `00-项目管理/开发准备.md` 固定块 fail-closed：五字段齐备 ∧ 必要项≥1 ∧ 未通过项=0 ∧ 最近复查为日期，缺项列明拒绝进入自动推进）；新增 `开发准备.md` 模板（规范升 v2.1.4：§4.6 新节＋§十模板索引 40 件）；使用手册新增「二、首次使用（开发准备引导）」节。套件 529→540/0（净增 11 断言）。
> **宿主要求**：建议 DSH 0.1.7-rc.2 起（0.1.7 声明式预设机制：包内 `presets/agent-preset.patch.yml` 自动生成预设声明层，无需手工处理）；v2.9.0 实测于 DSH 桌面版（Electron，desktop profile）　|　规范：项目目录及协同开发规范 **v2.1**（六区结构，本文档 v2.1.4）

## 版本与能力速览（v2.9.0）

- **三阶段工作流**：交互态设计（grill-me 决策清点开场问档）→ goal 驱动单包开发（一次授权多包连跑，五态流水线）→ 验收修复循环（含审核员修复审查）
- **两类任务场景**：新产品全流程 / 修改已有系统（场景1：现状研究中+目标代码区约束）；另有**技术调研储备**（场景2，独立终态不进开发）
- **首次使用引导与开工门禁（v2.9.0 新增）**：新会话首次对话先探查后告知（插件级 3 项＋项目级 6 项，只列缺失/未验证项，零副作用）；按需授权逐项补齐；`enter_auto_mode` 开发准备门禁 fail-closed（`00-项目管理/开发准备.md` 记录不齐即拒并列缺项）；远程仓库/测试服务器允许「不适用」须写理由，codegraph 不自动降级
- **对话形态纪律（v2.8.0 新增）**：全部人读消息 answer-first + 结尾唯一下一步 + 首尾双问自检 + 分组 ≤5（证据优先于简洁）；提问纪律（一次一决策点/选项 ≤4 推荐置顶/优先卡片提问）；过程消息一行制；不采用项成文（状态.md 唯一真源不散文重述／不删限定词／证据·债务清单不设条数上限／输出更短非目标）
- **子代理模型路由与会话覆盖（v2.7.0 新增）**：每角色默认+降级双槽路由（持久配置现读、原子写、不落在预设同步树）；429/额度类错误自动切降级（G1 硬闸门：插件独占先于宿主重试，不消耗默认模型重试预算；降级失败即停不循环；非适用错误不误降级）；会话临时改模（缺省仅当次主会话、epoch 隔离、在跑 child 快照不受影响、压缩不丢）与显式永久改默认/降级（原子保存、新派工即生效）；「仅下一次」一次性语义明确拒绝不落状态
- **挂载防回归（v2.7.1）**：delegation 组本地模块行必须导出 `apply` 的装配断言（config-check T3h，含缺 apply 夹具检红演算）；注册与更新前体检**双 profile 覆盖**（web 走 CLI、desktop 走 Electron 管理）
- **SpecKit 证据裁决口径（v2.6.1 起）**：AC 证据核验表「证据等级/逐项状态」列；修复包未决澄清闸门、根因初判、正当扩围第三态、上游指针；场景2 裁决三态、反证强制与 `ASSUMPTION` 标记
- **运行安全三层机制（v2.4.x）**：派工生成**三问裁定**；开发员**五条刹车纪律 + 心跳**；**看门狗**（B/C 后台派工、调度员轮内 tick 值班，L0 观察→L1 steer→L2 中断→L3 停机）；恢复轮孤儿接管；审核员计划审核第 5 项判断题
- **调度可靠性机器层**：预算台账 = 环节级 WAL/结算账本（schema v2 身份行 + runId/attempt/派工前阶段/结算后阶段/candidateCommit/evidencePath 六列）、runId 精确结算、派工返回六态（DONE/DONE_WITH_CONCERNS/NEEDS_CONTEXT/BLOCKED/FAILED/INTERRUPTED）、dispatch_status 四方一致检查+续跑建议、旧台账 v1→v2 迁移、故障注入五项回归套件
- **质量闸门**：任务包改动点「消费/产出」接口契约 + 计划审核跨改动点冲突扫描；验收「无证或不可证伪即驳回」；修复包 T0 根因→T1 RED→T2 GREEN→T3 回归证据链；代码审查 loadBearing 承重标注；P1-8 审核纪律（不机械重跑/选择性复验/证据缺失驳回）
- **预算纪律**：按包分档三硬上限（小包 4/6/24、大包 8/8/48，派工即计次），token 纯统计、无费用概念
- **与 1.0（orchestrator）并存不替代**：两插件各自独立，按会话独占加载

## 安装

本仓库为**发布镜像**（只含最新版本）。安装包：`05-交付/安装包/dsh-orchestrator2-v2.9.0/`（或同名 zip 解压到本地目录后按目录安装）。

**web 版（`dsh web`，profile=web，CLI 一条命令）：**

```bash
dsh plugin --profile web add link:/路径/dsh-orchestrator2-v2.9.0
```

**桌面版（Electron，profile=desktop，由应用专属管理，CLI 写入会被拒 `managed exclusively by the Electron application`）：**

1. 打开桌面版**插件管理**界面（设置 → 插件），添加/更新插件，方式选「本地目录（link）」，指向 `…/dsh-orchestrator2-v2.9.0` 包目录；
2. 若界面不可用或需脚本化，可用**手工三件套**（操作前备份原文件）：① 改 `profiles/desktop/package.json` 的 link 依赖行指向新包目录；② 同步 `pnpm-lock.yaml` 对应两行；③ 把 `node_modules/dsh-orchestrator2` junction 重指到新包目录。

**两端通用**：装完**完全退出并重启**（桌面版注意先退出托盘进程，避免旧实例占端口）；新建会话在预设选择器选「自动开发调度器2.0」。重启前建议体检：`node "$env:APPDATA\npm\node_modules\@deepseek-ai\dsh\lib\bin.js" web --dump-config`——① 组合树含 `preset-orchestrator2`；② 零死引用；③ 注册指向新包。详见包根 `测试入口说明.md` 与包内 `presets/orchestrator2/docs/使用手册.md`。

> 注：0.1.7 起预设走声明式机制（包内 `presets/agent-preset.patch.yml` 在宿主启动时自动把预设声明进组合树）；旧版「裸目录拷贝到 `~/.dsh/.agent-presets`」方式已随 0.1.7 移除，勿再用。
